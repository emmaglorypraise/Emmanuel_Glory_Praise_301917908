**Case study:** Ride-Hailing System

## Case study

This project explores the design and implementation of a database for a fictional, single-city ride-hailing system. The system manages customers, drivers, vehicles, trip requests, trip statuses and fares.

PostgreSQL is used for the structured relational data, including customer, driver, vehicle, trip and trip-status history records. MongoDB is used to model flexible trip activity events. The five portfolios cover relational database design, query processing and optimisation, transactions and concurrency, NoSQL data modelling, and a proposed distributed/cloud database design.

## Portfolio folders

- [**Portfolio 1 – Database Design and Modelling**](portfolio-1-database-design/): relational design, ER diagram, normalisation, PostgreSQL schema, sample data, constraint tests and screenshots.
- [**Portfolio 2 – Query Processing and Optimisation**](portfolio-2-query-optimisation/): SQL queries, execution plans, indexed and unindexed benchmark runs, performance analysis and screenshots.
- [**Portfolio 3 – Transactions and Concurrency**](portfolio-3-transactions-concurrency/): transaction exercises covering `COMMIT`, `ROLLBACK`, conditional updates, two-session concurrency tests and screenshots.
- [**Portfolio 4 – NoSQL and Advanced Data Models**](portfolio-4-nosql/): MongoDB setup notes, document model, event data, queries and execution screenshots.
- [**Portfolio 5 – Distributed and Cloud Database Exercise**](portfolio-5-distributed-cloud/): discussion and proposed design for MongoDB replication, availability, sharding and cloud deployment considerations.

Each portfolio folder contains its relevant scripts, documentation and execution evidence.
